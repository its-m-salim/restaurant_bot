# 📋 ТЗ: Telegram-бот «Меню ресторана»

## 🎯 Цель задачи

Закрепить темы прошлого урока (Aiogram + PostgreSQL + FSM + работа с файлами) на практике.

Нужно написать Telegram-бота, который:

- различает **обычного пользователя** и **админа**;
- показывает меню ресторана по категориям в виде кнопок;
- при выборе блюда отправляет фото, цену и описание;
- позволяет оформить заказ (кол-во, номер столика, имя);
- позволяет админу полностью управлять меню (CRUD).

---

## 🗄 Структура базы данных

### Таблица `users`

| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL PRIMARY KEY | внутренний ID |
| telegram_id | BIGINT UNIQUE NOT NULL | ID пользователя в Telegram |
| username | TEXT | @username пользователя |
| is_admin | BOOLEAN DEFAULT FALSE | является ли пользователь админом |

**Логика:** когда пользователь пишет `/start`, бот проверяет — есть ли `telegram_id` в таблице `users`.

- Если **нет** — создаём новую запись (`is_admin = FALSE`).
- Если **есть** — смотрим поле `is_admin`:
  - `is_admin = TRUE` → показываем админ-меню (CRUD меню ресторана).
  - `is_admin = FALSE` → показываем обычное меню (категории → блюда → заказ).

---

### Таблица `categories`

| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL PRIMARY KEY | ID категории |
| name | TEXT NOT NULL | название (Супы, Напитки, Горячее и т.д.) |

### Таблица `dishes`

| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL PRIMARY KEY | ID блюда |
| category_id | INTEGER REFERENCES categories(id) | к какой категории относится |
| name | TEXT NOT NULL | название блюда |
| description | TEXT | описание блюда |
| price | NUMERIC NOT NULL | цена |
| photo_file_id | TEXT | file_id фотографии блюда (как в уроке — сохраняем только file_id, саму фотографию не скачиваем) |

---

### Таблица `orders`

| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL PRIMARY KEY | ID заказа |
| telegram_id | BIGINT NOT NULL | кто заказал |
| dish_id | INTEGER REFERENCES dishes(id) | какое блюдо |
| quantity | INTEGER NOT NULL | количество |
| table_number | INTEGER NOT NULL | номер столика |
| customer_name | TEXT NOT NULL | имя, которое ввёл пользователь |
| created_at | TIMESTAMP DEFAULT NOW() | когда сделан заказ |

## 👤 Сценарий для обычного пользователя

1. `/start` → бот проверяет пользователя в БД → показывает **список категорий** (кнопками, инлайн или reply — на твой выбор).
2. Пользователь нажимает на категорию → бот показывает **список блюд** этой категории (кнопками).
3. Пользователь нажимает на блюдо → бот отправляет:
   - фото блюда (`answer_photo` по `photo_file_id`);
   - цену;
   - описание;
   - кнопку **«Заказать»** внизу.
4. Пользователь нажимает **«Заказать»** → запускается FSM:
   - шаг 1: бот спрашивает **количество**;
   - шаг 2: бот спрашивает **номер столика**;
   - шаг 3: бот спрашивает **имя**;
5. После заполнения всех шагов — заказ сохраняется в таблицу `orders`, пользователю приходит подтверждение (например: «✅ Заказ оформлен! Столик 5, Плов x2»).

---

## 🛠 Сценарий для админа (`is_admin = TRUE`)

При `/start` вместо обычного меню админ видит меню управления с CRUD-операциями:

| Команда / кнопка | Что делает |
|---|---|
| ➕ Добавить блюдо | FSM: спрашивает категорию → название → описание → цену → фото → сохраняет в `dishes` |
| ✏️ Изменить блюдо | выбор блюда из списка → выбор поля → ввод нового значения → UPDATE |
| ❌ Удалить блюдо | выбор блюда из списка → подтверждение → DELETE |
| 📋 Список блюд | SELECT всех блюд, вывод текстом (название, цена, категория) |

Категории можно либо создавать заранее вручную в БД, либо (по желанию, необязательно) добавить админу возможность создавать категории тем же способом, что и блюда.

## 🔄 FSM-состояния (пример, можно называть иначе)

```python
class OrderStates(StatesGroup):
    waiting_quantity = State()
    waiting_table = State()
    waiting_name = State()

class AddDishStates(StatesGroup):
    waiting_category = State()
    waiting_name = State()
    waiting_description = State()
    waiting_price = State()
    waiting_photo = State()
```

## ⚠️ Важные моменты

- Фотографии блюд **не скачиваются на диск** — сохраняется только `photo_file_id`, как в уроке.
- Все запросы к БД — только через параметризованные запросы (`$1, $2, ...`), никаких f-строк в SQL.
- Проверка `is_admin` должна происходить **при каждом `/start`**, а не один раз при регистрации — админ мог быть назначен позже вручную в БД.
- У обычного пользователя не должно быть доступа к командам/кнопкам управления меню, даже если он знает их название.

- [ ] Новый пользователь при `/start` добавляется в `users`.
- [ ] Обычный пользователь видит категории → блюда → карточку блюда → может оформить заказ.
- [ ] Заказ полностью сохраняется в `orders` (кол-во, столик, имя, кто заказал, что заказал).
- [ ] Админ может добавить, изменить, удалить и посмотреть список блюд.
- [ ] Фото блюда хранится как `file_id`, без скачивания на диск.
